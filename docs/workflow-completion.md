# 研发与分析任务深化（v0.5）

基线：953afb9；范围：本仓全栈开发。用户已授权按上一轮能力清单实施。本文件记录实施与验收依据，不表示真实企业外部系统已经接通。

## 业务规则和验收

- R1 数据完整性：不得静默截断分组；0、false、null 分组不同；日期边界一致。超过限制明确失败并要求缩小范围。
- R2 调度：领取任务与原状态比较，取消不可复活；失败/中断可由原有任务编辑权限重试，重新检查审批与权限。
- R3 研发：结构化方案覆盖目标、可行性、缺口、每仓影响、修改路径、验证及回退；不充分/不可行方案不可执行；执行层约束修改范围并保护既有验证文件。
- R4 审批：以方案版本和资源为单位记录批准；各资源负责人仅批准自己负责资源；所有资源批准且授权仍有效后执行；改方案废弃批准。
- R5 分析：任务说明明确决策、约束和假设；批准时冻结指标和口径配置；输出保留计算证据、来源时间、校验与局限；支持受控跨源维度对齐、比较和情景计算，不把相关性声明为因果。
- R6 行动：分配期限、负责人、衡量指标；员工仅看自己的动作与反馈，不因此获得底层数据权限；站内待办与通知；保留反馈历史；支持授权负责人复测效果、将建议转研发任务。
- R7 连接：HTTPS GET 白名单、同源分页、有限重试、总量/时间界限，配置校验不持有数据库写锁；没有具体企业协议的专用适配不假装完成。
- R8 交付：保持旧任务可查看；新任务使用新约束；测试覆盖正常、权限、版本、取消、完整性及异常路径；前端类型检查与构建通过。
- R9 验收：各资源负责人仅审阅、验收本资源结果；方案版本、结果及验收人权限仍有效，全部资源齐备后才完成。新版研发代码与验证时指纹不一致时拒绝验收，必须重新验证。

## 分工和接口方向

- 研发：worker.py、development.py，负责研发方案、影响分析、执行边界、每仓进度、交付包。
- 分析：analytics.py、analysis_worker.py、analysis.py，负责分析计算、快照、证据、受控比较与情景计算。
- 界面：frontend/src，沿用现有 React 页面与组件；为方案、证据、审批、行动增加清晰入口和错误状态。
- 集成：main.py、platform.py、http_connector.py、orchestration.py、actions.py、sources.py；负责资源审批、领取/重试、连接配置和行动闭环；acceptance.py 负责逐资源结果验收。

扩展模块使用独立 init 函数与路由；主程序注册。新增数据库列采用保留数据的加法迁移。测试独立临时数据库，不访问真实业务系统。

## 交付边界

本轮交付本地可运行的平台能力及受控适配接口。真实 ERP/CRM 鉴权、模型质量、Docker/CI 发布、企业通知渠道、真实效果归因需要具体企业配置及数据，分别记录验证情况。完整关系型跨库 JOIN、任意 DAG、生产自动回滚与外部自动发布不以本轮的受控基础实现替代。
